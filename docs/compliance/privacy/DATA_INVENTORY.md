# Privacy Data Inventory + Classification Register (Agent B, Wave 1/2)

Controller-obligation categories mapped to verified tables/fields.
Source of truth for what erasure/export must cover.

| # | Category | Tables / fields | Notes |
|---|---|---|---|
| 1 | Identity & account | `users`: email, full_name, username, avatar_url, provider, provider_user_id, google_id, auth_provider, password_hash, has_password, email_verified, pending_email, last_login_at, preferences, deletion_{requested,scheduled}_at, deletion_notice_stage | Email unique among live rows only — freed address re-registers post-purge. `provider_user_id`/google_id = third-party identity linkage. |
| 2 | Auth secrets & sessions (PG) | `password_reset_tokens`: user_id, token_hash (sha256), expires_at, request_ip; `api_keys`: user_id/org_id/issued_by, name, key_prefix, key_hash (sha256 only), policies/IP rules/model perms | Raw keys/reset tokens never stored. `request_ip` is PII-adjacent. |
| 3 | Provider credentials | `providers`: user_id/org_id, name, provider_type, **credentials_encrypted (Fernet)**, metadata_ | Encrypted at rest. Rotation/revocation API ownership open (B vs C) — see DSR.md integration notes. |
| 4 | Conversations & messages (highest sensitivity) | `conversations`: user_id, title, provider/model refs, branch lineage; `messages`: user_id, conversation_id, role, **content (plaintext)**, metadata_, client_key, session_id (JWT sid), usage/cost; `message_versions`: content snapshots; `generation_runs`: content, key/provider/model refs | **Plaintext content at rest** — no encryption (unlike prompt logs). Largest erasure surface. `session_id` links messages to auth sessions. |
| 5 | Attachments & object storage | `attachments`: user/message/conversation refs, filename, mime, storage_path (relative, never serialized), extracted_text; bytes via `services/gateway/attachments.py` | `extracted_text` duplicates file bytes into PG. Purge deletes rows + disk bytes. |
| 6 | Prompt-log ledger (quasi-content) | `prompt_logging_settings`: user/org scope, enabled/mode, capture_input/output, **retention_days (NULL = forever)**, version; `prompt_logs`: user/org/key/conversation/provider/model refs, request_id, **input/output_cipher (Fernet)**, chars, tokens, error_code, content_expired, expires_at | Append-only; expiry NULLs ciphers, metadata rows kept. Capture is fail-open. Bodies bounded 512K chars. |
| 7 | Request/usage telemetry | `request_logs`: user/org/key/conversation/message/provider/model refs, tokens, costs, status — **no payloads**; `api_request_logs` (gateway): + ip_address, user_agent, device/browser/platform, country/city/region; `usage_daily_aggregates`: per-(day,user,provider,model) counts/tokens/costs | Gateway logs carry IP + geo + UA = personal data. Aggregates are counts-only. |
| 8 | Search index (derived content) | `conversation_search_index`: user/conversation/message refs, title, **content (plaintext copy)**, provider/model names, tsv | Content duplicated from messages; DB-CASCADEs on conversation delete. |
| 9 | Guardrail triggers (excerpts) | `guardrail_triggers`: user/org/key/provider/model refs, request/generation ids, category/severity/action, **input_excerpt/output_excerpt (plaintext)**, reason; append-only, no soft-delete | Excerpts = content copies outside the message store. No excerpt redaction/expiry mechanism exists. |
| 10 | Sharing | `conversation_shares`: conversation/user refs, share_token (public bearer), is_public, view_count; Valkey `tollma:share:<token>` lookup cache | Public links extend the erasure perimeter. |
| 11 | Billing-adjacent | `organizations`: name/slug/description/website/industry/location, root_user_id, audit_retention_days (365d default), max_spend; memberships, invitations, audit_logs, notifications; `benchmark_runs`: user/org refs, labels, conditions (never bodies — 422 enforced) | No dedicated billing table (usage/cost columns only). Confirm with orchestrator if billing lives elsewhere. |
| 12 | Valkey (ephemeral personal data) | `session:{sid}` + `sessions:{user_id}` SET; `tollma:conversation:{id}`, `messages:{id}`, `usage:{user}:{conv}`, `generation:{gen_id}`/`conv:{conv_id}` (**current_content** — live generation text); `analytics:{user}:{digest}`, `search:{user}:{digest}`; `ratelimit:*`, `login_attempts:{sha256(email\|ip)}` (email never in key); `keytomb:{hash}`; `verify_email:*`, `oauth_state:*`; `gateway:response:*` (reserved, no writers); metrics counters | Generation entries hold message content transiently. Session store is Valkey-only (fail-closed auth). |
| 13 | Email / notifications | `services/email/service.py` dev outbox + lifecycle mails (requested/reminder-7d/reminder-1d/purged/restored, keyed by address) | No marketing/newsletter surface — consent `marketing` stays reserved. |

Not present in this codebase (verified): **Qdrant / any vector store** (search is PG tsvector), **ARQ** (jobs are APScheduler). Deletion propagation covers PG + object storage + Valkey. Re-check if an embeddings store is ever introduced.
